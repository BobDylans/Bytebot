# 需求与范围

## 1. 问题定义
- 用户想解决什么问题？（检索准确率、引用可追溯、自部署可控）
- 典型使用场景是什么？（企业内知识库、项目文档检索）

## 2. 用户故事（草案）
- 作为用户，我能导入一批文档并建立索引
- 作为用户，我能以自然语言提问并得到可引用的回答
- 作为管理员，我能控制数据源、权限与更新频率

## 3. MVP 范围（最小闭环）
- 文档导入：本地目录/文件上传（格式：PDF/MD/TXT）
- 混合检索：向量检索 + 关键词检索
- 回答生成：LLM 生成答案并带引用

## 4. 非功能需求（优先）
- 可自部署（本地/内网）
- 可观测（最小日志与指标）
- 可复现（固定模型版本与参数）

## 5. 成功指标（MVP）
- 50 条测试问题中，引用正确率 >= 80%
- 单次查询 P95 < 5s（本地单机）

## 6. 约束与假设
- 文档规模：1k - 10k 文件
- 数据权限：默认同一租户访问

## 本阶段完成标准
- MVP 范围锁定且可执行
- 成功指标可度量
- 输入数据清单确定
## 7. 已确认的约束与假设（MVP）
- 部署形态：单机（内网）
- 数据来源：内网文件目录
- 权限模型：多租户（tenant_id 隔离）
- 接口安全：内网无认证
- UI 形态：简易 Web UI（后续独立前端）
- 文档格式：PDF / MD / TXT + DOCX
- 切分策略：段落优先 + 长段再切
- Embedding：外部 API
- Rerank：MVP 不做
- 观测：基本日志
